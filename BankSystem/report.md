# 银行综合管理系统 课程设计报告

**课程名称**：数据结构与算法 / C++ 程序设计  
**项目名称**：银行综合管理系统 v1.0  
**开发语言**：C++14  
**运行平台**：Windows（控制台）

## 一、需求分析

### 1.1 系统背景

银行业务涉及多类型用户（管理员、职员、客户）、多类型数据（账户、银行卡、交易、网点）以及复杂的业务逻辑（优先排队、路径导航、信用评分）。本系统以教学为目的，综合运用链表、栈、队列、优先队列、图、广义表等核心数据结构，实现一个完整的银行管理信息系统。

### 1.2 功能需求

系统共 10 个功能模块：

1. **职员管理**：职员信息的增删改查，支持按工号/姓名/部门检索，管理员可重置职员密码。
2. **客户账户管理**：客户注册、信息维护、注销；广义表展示客户及其名下银行卡层级结构。
3. **银行卡管理**：开卡/销卡/冻结/解冻；支持借记卡、储蓄卡、信用卡三种类型；自动生成 16 位卡号。
4. **存贷款业务**：存款、取款、转账、申请贷款、还款，实时更新账户余额。
5. **业务查询**：交易记录的多维度查询（日期范围、交易类型、金额范围、客户类型）及收支统计。
6. **排队管理**：VIP 优先排队（优先队列），普通排队（链式队列），服务窗口管理，客户评分，每日报表。
7. **网点查询导航**：图结构建模网点路网，Dijkstra 算法求最短路径，BFS 枚举可达路径，ASCII 地图展示。
8. **智能管理**：大额/频繁交易异常检测，信用评分模型，贷款风控审批，客户资产统计分析。
9. **系统主界面**：管理员/职员/客户三角色登录，会话状态管理，角色权限隔离。
10. **数据持久化**：所有数据以固定大小结构体序列化为二进制文件，程序重启后数据保留。

### 1.3 非功能需求

- **界面**：Windows 控制台彩色字符 UI，不依赖外部 GUI 库。
- **数据结构**：核心容器（链表、栈、队列、堆、图、广义表）全部手写实现，不使用 STL 容器。
- **编译**：g++ -std=c++14，仅使用 STL 算法辅助函数（`std::swap`、`std::function`）。

## 三、数据结构设计

### 3.1 双向链表 `LinkedList<T>`

**用途**：存储职员、客户、银行卡、交易记录、网点等所有主数据。

**核心操作时间复杂度**：

| 操作 | 复杂度 |
|------|--------|
| `push_back` / `push_front` | $O(1)$ |
| `find_if` | $O(n)$ |
| `remove_if` | $O(n)$ |
| `forEach` | $O(n)$ |

**关键实现**：

```cpp
template<typename T>
class LinkedList {
    struct Node { T data; Node* prev; Node* next; };
    Node* head_; Node* tail_; int size_;
public:
    T* find_if(std::function<bool(const T&)> pred);
    int remove_if(std::function<bool(const T&)> pred);
    void forEach(std::function<void(const T&)> cb) const;
    // ...
};
```

### 3.2 链式栈 `Stack<T>`

**用途**：历史操作记录（预留扩展接口）。

**核心操作**：`push` / `pop` / `peek`，均为 $O(1)$。

### 3.3 链式队列 `Queue<T>`

**用途**：普通客户排队队列（先来先服务 FIFO）。

**核心操作**：`enqueue` / `dequeue`，均为 $O(1)$。

### 3.4 最大二叉堆 `PriorityQueue<T>`

**用途**：VIP 客户优先排队，支持 VIP 客户插队普通客户之前。

**设计**：要求模板参数 `T` 实现 `operator<`。`QueueTicket` 的比较规则：
- VIP 类型 > 普通类型（高优先级先出队）
- 同类型中，号码小的优先（先取号先服务）

**核心操作时间复杂度**：

| 操作 | 复杂度 |
|------|--------|
| `push`（siftUp）| $O(\log n)$ |
| `pop`（siftDown）| $O(\log n)$ |
| `top` | $O(1)$ |

### 3.5 图 `Graph`（邻接矩阵）

**用途**：银行网点路网建模，支持最短路径查询和可达性判断。

**实现**：
- 顶点数上限 `MAXV = 50`
- `double dist[MAXV][MAXV]`，`INF = 1e18` 表示不可达
- 顶点名称数组 `char verts[MAXV][MAX_NAME]`

**算法**：
- **Dijkstra**：$O(V^2)$，求单源最短路径，返回路径字符串及总距离。
- **BFS**：$O(V + E)$，枚举从指定源点可达的所有顶点。

### 3.6 广义表 `GList`

**用途**：展示客户及其名下银行卡的层级结构，体现广义表的嵌套特性。

**结构**：

```
( 客户A (卡1 卡2 卡3) , 客户B (卡4) , 客户C () )
```

节点类型分为原子节点（`ATOM`，存储字符串）和子表节点（`LIST`，递归嵌套）。

## 四、各模块详细设计

### 4.1 模块1：职员管理（`EmployeeManager`）

**数据存储**：`LinkedList<Employee>`，持久化至 `data\employees.dat`。

**主要功能**：
- **登录验证**：`login(id, pwd)` 返回 `Employee*`，密码明文比对（教学环境）。
- **添加职员**：生成带时间戳的唯一 ID，`strncpy` 写入字段。
- **软删除**：`isActive = false`，数据保留在文件中。
- **密码修改**：职员可改自己密码，管理员可重置任意职员密码。
- **默认管理员**：首次加载数据为空时自动创建 `admin / admin123`。

**流程图（登录）**：

```
输入工号+密码 → find_if 遍历链表 → 比对密码 → 成功：写入 g_session → 失败：提示重试
```

### 4.2 模块2：客户账户管理（`CustomerManager`）

**数据存储**：`LinkedList<Customer>`，持久化至 `data\customers.dat`。

**广义表展示**（`showGList`）：
```
客户层级结构：
( [C001]张三 ( [6222...]借记卡 [6222...]信用卡 ) ,
  [C002]李四 ( [6222...]储蓄卡 ) )
```

**VIP 升级逻辑**：客户月收入 > 5000 或金融资产 > 100000 时，职员可手动设置为 VIP 类型。

### 4.3 模块3：银行卡管理（`BankCardManager`）

**卡号生成规则**：`"6222"` + 8位序号 + 4位时间戳尾数，共 16 位。

**三种卡类型**：
- **借记卡**（DEBIT）：余额不可为负
- **储蓄卡**（SAVINGS）：支持按月计息，利率 0.35%/月
- **信用卡**（CREDIT）：支持贷款额度，贷款利率 0.5%/月

**余额更新**：`updateBalance(cardId, delta)` 供 `TransactionManager` 调用。

### 4.4 模块4+5：存贷款业务 & 业务查询（`TransactionManager`）

**交易类型**：存款、取款、转账、利息、贷款、还款（`TxnType` 枚举）。

**大额交易标记**：金额超过 50000 元自动设置 `isSuspicious = true`，供智能模块检测。

**月利息结算**（`settleInterest`）：遍历所有储蓄卡和信用卡，按余额/贷款额计算并生成利息交易记录。

**查询设计**：
- 按日期范围：字符串前缀比较（`strncmp`）
- 按金额范围：`amount >= low && amount <= high`
- 支持组合过滤，结果按时间倒序展示

### 4.5 模块6：排队管理（`BankQueueManager`）

**双队列设计**：

```
客户取号
  ├── VIP 客户 → PriorityQueue<QueueTicket>（优先队列）
  └── 普通客户 → Queue<QueueTicket>（链式队列）

窗口叫号
  ├── VIP 窗口 → 先从优先队列取，无则从普通队列取
  └── 普通窗口 → 只从普通队列取
```

**号码生成**：全局自增计数器，VIP 前缀 `V`，普通前缀 `N`，如 `V001`、`N003`。

**服务评分**：客户对本次服务打 1-5 分，纳入每日统计平均分。

### 4.6 模块7：网点查询导航（`BranchGraphManager`）

**图建模**：每个 `Branch` 网点对应图中一个顶点，网点间的道路对应带权边（距离，km）。

**预置数据**（首次运行自动初始化）：

```
北京总行 ── 3.2km ── 中关村支行 ── 4.5km ── 上地支行
    │                     │
  2.8km                 5.1km
    │                     │
朝阳支行 ── 6.0km ── 国贸支行 ── 3.8km ── 望京支行
```

**Dijkstra 最短路径**示例：
```
北京总行 → 国贸支行：北京总行 → 朝阳支行 → 国贸支行，总距离 8.8 km
```

### 4.7 模块8：智能管理（`SmartManager`）

**三大创新功能**：

#### (1) 交易异常检测

检测规则（OR 逻辑）：
- 单笔金额 > 50000 元（大额交易）
- 同一客户 24 小时内交易次数 > 5 次（频繁交易）

#### (2) 信用评分模型

评分公式（满分 1000 分）：

$$\text{score} = \min(1000,\ S_{\text{asset}} + S_{\text{ratio}} + S_{\text{loan}} + S_{\text{anomaly}})$$

| 分项 | 说明 | 最高分 |
|------|------|--------|
| $S_{\text{asset}}$ | 金融资产（每10万+100分） | 400 |
| $S_{\text{ratio}}$ | 收支比（收入/支出越高越好） | 300 |
| $S_{\text{loan}}$ | 无贷款 +200，有贷款按比例扣减 | 200 |
| $S_{\text{anomaly}}$ | 无异常 +100，每条异常 -30 | 100 |

#### (3) 贷款风控审批

审批规则：
- 信用分 < 400：直接拒绝
- 贷款金额 > 月收入 × 24：超出上限，拒绝
- 月还款（等额本息估算）> 月收入 × 50%：还款压力过大，拒绝
- 通过以上校验则审批通过

## 六、数据持久化设计

### 6.1 二进制序列化

所有数据结构体成员均为固定大小（`char[]` 数组 + 基本类型），直接以 `fwrite`/`fread` 按字节序列化。

**文件格式**：

```
[4字节 int: count] [sizeof(T) × count: 数据]
```

**模板函数**：

```cpp
template<typename T>
bool saveList(const char* path, LinkedList<T>& list);

template<typename T>
bool loadList(const char* path, LinkedList<T>& list);
```

### 6.2 图的持久化

图单独序列化：先写顶点数 + 顶点名称数组，再写邻接矩阵（`double[50][50]`）。

### 6.3 数据目录

程序启动时调用 `ensureDataDir()`，使用 Windows `_mkdir("data")` 自动创建 `data\` 目录。

## 七、系统安全设计

### 7.1 权限控制

全局 `Session g_session` 记录当前登录用户的角色（`Role` 枚举）、工号/客户号、姓名。每个子菜单入口通过判断 `g_session.role` 实现角色权限隔离：管理员可访问所有模块，职员不可访问职员管理的管理功能，客户只能操作自己的数据。

### 7.2 密码保护

控制台密码输入使用 `_getch()` 逐字符读取，不回显，显示 `*` 占位。

### 7.3 操作确认

删除账户、销毁银行卡等不可逆操作均通过 `confirm()` 二次确认（需输入 `y` 确认）。

### 7.4 软删除

职员和客户的删除操作均采用软删除（`isActive = false`），数据保留在文件中，便于审计追溯。

## 九、总结与反思

### 9.1 已实现功能

- ✅ 10 个功能模块全部实现
- ✅ 6 种自定义数据结构手写实现
- ✅ 二进制文件持久化
- ✅ Windows 控制台彩色 UI
- ✅ 三角色权限管理
- ✅ Dijkstra + BFS 路径算法
- ✅ 信用评分与贷款风控模型
- ✅ VIP 优先队列排号

### 9.2 设计亮点

1. **模板化数据结构**：`LinkedList<T>`、`PriorityQueue<T>` 等模板类可复用于任意业务数据，代码复用率高。
2. **广义表可视化**：用广义表直观展示客户-银行卡层级嵌套关系，体现数据结构课程核心内容。
3. **双队列排队系统**：优先队列与普通队列协同工作，贴近真实银行排队场景。
4. **图+Dijkstra导航**：将银行网点抽象为图，路径导航算法工程实用性强。

### 9.3 局限与改进方向

1. 密码以明文存储，实际应使用哈希（如 SHA-256）处理。
2. 二进制文件未加版本号，结构体变更后旧文件不兼容。
3. 排队系统中优先队列容量固定（最大堆数组），可改为动态扩容。
4. 图的邻接矩阵空间为 $O(V^2)$，网点数量多时可改用邻接表。
